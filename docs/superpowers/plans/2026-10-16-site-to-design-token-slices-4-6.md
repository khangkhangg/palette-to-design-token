# Site to Design Token — Slices 4–6 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Take the extension from "Pro is a flag" to a shippable product: $1.49 PayPal checkout and license keys on vietnamcos.com, all 7 languages, and a Chrome Web Store package.

**Architecture:** A self-contained PHP add-on in `server/` (deployed to `/var/www/duykhang/companies/palette/` on spo2x, served at `vietnamcos.com/palette/…`) that `require`s the companies app's config, functions, rate limiter and PayPal helpers but changes no companies file; it owns two tables and its own PayPal webhook. The extension talks to it over CORS (`verify`) and receives keys from the checkout page via `externally_connectable`. Translations are JSON dictionaries; the store package is generated by scripts.

**Tech Stack:** PHP 8.4 + mysqli (as companies), PayPal REST v2 via companies' `pp_api`, PayPal JS SDK on the checkout page; extension as in slices 1–3 (TS, Preact, Vitest, Playwright).

**Spec:** `docs/superpowers/specs/2026-10-16-palette-to-design-token-design.md` (§3 tax, §6.3, §7, §8, §9, §10, §12 slices 4–6)

## Global Constraints

- Price **1.49 USD**. Key format **`SDT-XXXX-XXXX-XXXX`** (Crockford base32, 60 random bits from `random_bytes`).
- Refund line (exact): "All sales are final. Because Pro unlocks instantly and costs $1.49, we do not offer refunds after purchase." Consent checkbox (exact): "I understand purchases are final and not refundable." — required; consent time stored on the order.
- Tax: admin setting `tax_mode` = `none` | `ca`; `ca` adds **7.25%** only when the buyer selects country US + state CA → **$1.60**; amount computed server-side when the order is created. Default per owner decision (see Open question).
- Server changes **no** companies file; it uses only `config.php` ($conn, `EMAIL_FROM_ADDRESS`, `EMAIL_FROM_NAME`), `includes/functions.php` (`generateCSRFToken`, `verifyCSRFToken`, `getAdminSetting`), `includes/ip_rate_limit.php` (`checkRateLimit`), `includes/paypal.php` (`pp_settings`, `pp_ready`, `pp_api`, `pp_http` stub hook `$GLOBALS['pp_http']`). List them in `server/README.md` as the coupling contract.
- Settings live in `admin_settings` key **`palette`** (JSON).
- Rate limits: `verify` 30/min/IP; `resend` 3/hour/email and 10/hour/IP.
- `resend` always answers "If a key exists for that address, we sent it." (no address probing).
- Extension re-verifies at most every **30 days**; network failure keeps Pro; a revoked key turns Pro off.
- Languages (7): `en`, `zh-CN`, `hi`, `es`, `ar` (RTL), `fr`, `bn` — extension UI, checkout page, emails, store listing.
- No emoji in any UI or email; Font Awesome is not used in this product — inline SVG only.
- Server PHP tests are CLI scripts that refuse to run unless `SELECT DATABASE()` ends in `_test`.

## Open question for the owner (does not block Tasks 1–3, 8–10)

Default `tax_mode`. Owner said "collect California tax"; controller recommended none. Plan implements both; Task 5 seeds the default the owner picks.

## Review Focus

1. **Double fulfilment** — page capture and webhook racing on the same order must issue exactly one key and one email. Test in Task 4.
2. **Amount tampering** — the client never sends an amount; a capture whose amount/currency differs from the stored order is marked failed, no key. Test in Task 4.
3. **Key brute force / enumeration** — `verify` is rate-limited and answers identically for unknown and malformed keys; `resend` never reveals whether an email bought. Tests in Task 3.
4. **Extension offline / server down** — activation shows "Couldn't reach the server"; an already-active Pro survives a failed 30-day re-check. Test in Task 7.
5. **RTL and long translations** — Arabic mirrors; German-length strings don't overflow the 400 px popup (use `fr`/`hi` as the long cases). Test in Task 8.
